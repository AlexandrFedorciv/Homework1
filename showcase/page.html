How PartsBin works

1

Tell it what you have

Type parts (4x sg90, servo x4 and servo (4) all work) or drop a photo; a vision model lists what it sees and you fix the list.

2

Add constraints

Goal, skill, time and budget are optional. Tick "I can't solder" for breadboard-only builds.

3

AI designs, code checks

Claude proposes three projects as structured JSON. The app, not the AI, works out what you own, what's missing and what it costs, and verifies every constraint.

4

Fix what breaks

Projects that are too long, too hard or over budget go back to Claude with the reason and get replaced. You get the best three.

Reading a project card

  • ✓ you own it · ◐ you own some, need more · ✗ missing, with an indicative price in CZK.
  • The drawing shows every part: solid cards are yours, dashed red cards are to buy.
  • The chips at the bottom are the checks the app ran on that project.
  • The dark log above the results shows each step as it happens, including retries and replaced projects.

Live vs. offline

Claude (live) sends your parts to Claude from this page, using your own Claude account; the first time, the page asks your permission. Offline demo runs the same pipeline but answers from the %%GALLERY_PROJECTS%% built-in gallery projects, so it's instant and free. To show the self-check, it ignores your limits on the first try, just like a real model sometimes does.

About the project

PartsBin is my answer to Homework 1 · Fridge-to-Recipes: an app that takes what you have plus optional constraints and returns three suggestions, each with a full list marking what's missing, step-by-step instructions and an estimated time. Same shape, different fridge: electronics parts instead of ingredients, projects instead of recipes.

The full app is a TypeScript CLI and a small web server. This page runs the same core code, compiled for the browser, with Claude reached through the page instead of an API key.

What makes it more than a prompt

  • The AI is creative, the code is the referee. What you own, what's missing and what it costs are computed in code from a catalog of %%CATALOG_PARTS%% parts with aliases. SG90, 9g micro servo and servos are the same part; quantities count.
  • Self-check loop. Skill, time, budget, soldering, "uses your parts" and a mains-voltage safety rule are verified on every project. Failing ones are regenerated individually with the reasons.
  • Validated structured output. JSON Schema + zod; broken answers go back with the exact errors (up to 2 repairs).
  • Photo → parts with a vision model, and you confirm the list.
  • Generated parts drawings for every project, with 60+ component icons.
  • Provider-agnostic. Anthropic, any OpenAI-compatible API, or offline; the HTTP layer is plain fetch, no SDK.
  • %%GALLERY_PROJECTS%% gallery projects: beginner robotics (radar, robot cars, robot arm, walkers), home gadgets and security builds (Pi-hole, VPN, security key, RFID lock, alarms), with full step-by-step guides for the Pi-hole, RFID lock, radar and theremin.
